# 공유 보드 설정 (Supabase)

여러 명이 같은 조 편성을 함께 고칠 수 있게 하는 백엔드입니다.
설정 전까지 앱은 지금처럼 브라우저 안에서만 동작합니다.

## 데이터 모델

| | |
|---|---|
| `workspace` | 팀 하나당 한 줄. `key` 는 128비트 무작위 비밀값 — **이걸 아는 사람이 편집 권한자** |
| `board` | 워크스페이스 안에서 **한 달에 한 줄** (`period` = `2026-09`). `locked` 로 확정 |

달마다 테이블을 새로 만들지 않습니다. 테이블은 2개로 고정이고, 달은 줄로 늘어납니다.
`CREATE TABLE` 은 공개 키로 실행할 수 없고, 달마다 정책을 다시 만들어야 하며,
"전체 달 보기"가 불가능해지기 때문입니다.

## 보안 모델

두 테이블 모두 RLS 를 켜고 **정책을 하나도 만들지 않습니다.** 즉 클라이언트의 테이블
직접 접근은 완전히 막힙니다. 읽기/쓰기는 `security definer` 함수로만 가능하고, 이 함수들은
매번 workspace key 를 확인합니다.

그래서 공개 사이트에 노출되는 anon key 만으로는 **아무 것도 열람할 수 없습니다.**
실제 열쇠는 workspace key 이고, 이건 공유 링크에만 들어갑니다.

> 링크를 가진 사람은 누구나 편집할 수 있습니다. 팀 채팅처럼 닫힌 곳에만 공유하세요.
> 명단에 실명·학년이 들어있다는 점을 기억하세요. 유출되면 워크스페이스를 새로 만들면 됩니다.

동시 편집은 **낙관적 잠금**으로 처리합니다. 불러온 뒤 남이 먼저 저장했으면 덮어쓰지 않고
충돌로 거절합니다. 변경 감지는 `board_rev` (payload 없이 rev 만) 폴링이라 트래픽이 거의 없습니다.

## 설정 순서

1. https://supabase.com 에서 무료 프로젝트를 만듭니다 (카드 필요 없음).
2. SQL Editor 에 [`schema.sql`](schema.sql) 을 통째로 붙여넣고 실행합니다.
3. [`create-workspace.sql`](create-workspace.sql) 을 실행하고, 출력된 `key` 를 보관합니다.
4. Settings › API 에서 **Project URL** 과 **anon public key** 를 복사합니다.

## 무료 플랜 주의점

- 요금은 청구되지 않습니다. 한도를 넘으면 청구 대신 제한됩니다. Pro 는 직접 눌러야 올라갑니다.
- **약 1주일 미사용 시 프로젝트가 일시정지됩니다.** 학기 중 가끔 쓰는 도구라면
  쓰기 전에 대시보드에서 한 번 깨워야 할 수 있습니다.
